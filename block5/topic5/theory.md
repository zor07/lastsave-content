## Перегрузка методов

В этом разделе разберём перегрузку методов — механизм, с которым ты уже работал, просто не знал как он называется.

## Ты уже это делал

Вспомни, как мы писали конструкторы. Представь класс `Person`, у которого может быть два варианта создания — с именем и без:

```java
public class Person {
    private String name;

    public Person() {
        this.name = "Неизвестно";
    }

    public Person(String name) {
        this.name = name;
    }

    public String getName() {
        return name;
    }
}
```

Два конструктора с одинаковым именем `Person`, но с разными параметрами. Java отличает их по сигнатуре — по типу и количеству аргументов. Это и есть перегрузка.

То же самое работает для обычных методов.

## Перегрузка методов

Допустим, ты пишешь класс-помощник, который выводит информацию в консоль. Тебе нужно уметь выводить и числа, и текст:

```java
public class Printer {

    public void print(int value) {
        System.out.println("int: " + value);
    }

    public void print(double value) {
        System.out.println("double: " + value);
    }

    public void print(String value) {
        System.out.println("String: " + value);
    }
}
```

Три метода с одним именем `print`. Java знает, какой из них вызвать, по типу аргумента:

```java
Printer printer = new Printer();
printer.print(42);       // int: 42
printer.print(3.14);     // double: 3.14
printer.print("Привет"); // String: Привет
```

Без перегрузки пришлось бы придумывать разные имена: `printInt`, `printDouble`, `printString`. Перегрузка позволяет использовать одно имя для логически одинакового действия.

## Ты уже видел это в стандартной библиотеке

`System.out.println` — это перегруженный метод. Именно поэтому он принимает и `int`, и `String`, и `double`, и `boolean`. Под капотом у него десятки вариантов с разными параметрами. Теперь ты знаешь как это устроено.

## Правила перегрузки

Методы считаются перегрузками друг друга, если у них одинаковое имя, но отличается хотя бы одно из:
- тип параметров
- количество параметров
- порядок параметров

Примеры корректных перегрузок:

```java
public void process(int a) { }
public void process(int a, int b) { }        // другое количество
public void process(String a) { }            // другой тип
public void process(String a, int b) { }     // другой порядок
public void process(int a, String b) { }     // другой порядок
```

## Что не является перегрузкой

Возвращаемый тип — не часть сигнатуры. Два метода с одинаковыми параметрами, но разными типами возврата — это ошибка компиляции:

```java
public int getValue() { return 1; }
public String getValue() { return "один"; } // ошибка — нельзя
```

Java не сможет определить, какой из них вызвать, если написать просто `getValue()`.

Имена параметров тоже не влияют на сигнатуру. Эти два метода — не перегрузки, это дубликат:

```java
public void process(int a, int b) { }
public void process(int x, int y) { } // ошибка — сигнатура одинаковая
```

## Как Java выбирает нужный метод

Выбор происходит на этапе компиляции — не во время выполнения программы. Компилятор смотрит на тип аргументов при вызове и подбирает подходящую перегрузку. Если подходящей нет — ошибка компиляции.

```java
printer.print(42);       // компилятор видит int — вызывает print(int)
printer.print("Привет"); // компилятор видит String — вызывает print(String)
```

## Когда перегрузка уместна, а когда нет

Перегрузка уместна, когда методы делают одно и то же, но с разными типами данных. `print(int)` и `print(String)` — логически одно действие, просто разные входные данные.

Перегрузка не нужна, если методы делают разные вещи. Тогда лучше дать им разные имена — код станет понятнее.

Несмотря на то что тема выглядит просто, перегрузка встречается повсюду — в конструкторах, в стандартной библиотеке, в любом реальном проекте. Стоит хорошо её почувствовать на практике.
