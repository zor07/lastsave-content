## Классы и объекты

До этого момента мы писали код в процедурном стиле — программа выполняла последовательность инструкций. Эта последовательность могла быть витиеватой: условия, циклы, вызовы методов — но оставалась линейной. Метод получал данные снаружи, обрабатывал их и возвращал результат. Данные и логика существовали независимо друг от друга.

Java — объектно-ориентированный язык. В отличие от процедурного подхода, здесь программа строится на взаимодействии объектов. Последовательность инструкций сохраняется, но часть из них мы объединяем в абстрактные конструкции — объекты.

Объект — это модель какой-то сущности. Это может быть сущность из реального мира: Человек, Машина, Книга. Или абстрактная: Соединение, API, Калькулятор. В любом случае объект — это самостоятельная единица, которая что-то знает о себе и что-то умеет делать.

В коде объекты описываются **классами**. Класс — это шаблон, по которому создаются объекты.

Хорошая аналогия — таблица в Excel. Заголовок таблицы — это шаблон: он описывает какие колонки есть у каждой строки. Строки могут содержать разные значения, но все они соответствуют одному шаблону. Класс — это заголовок, объект — это строка.

Вспомним примеры: Человек, Калькулятор, Соединение, API. Запишем их как классы:

```java
public class Person {
}

public class Calculator {
}

public class Connection {
}

public class Api {
}
```

Пока это пустые шаблоны — различаются только названием.

## Поля

Объекты обладают свойствами:

- Человек — имя, возраст
- Калькулятор — текущий результат вычислений
- Соединение — хост, порт
- API — базовый адрес, токен

Набор свойств может быть любым — его определяет программист исходя из задачи. Если для задачи важен только возраст человека — имя можно не добавлять.

В Java свойства объекта называются **полями**. Поле — это переменная, объявленная внутри класса.

```java
public class Person {
    String name;
    int age;
}

public class Calculator {
    double result;
}

public class Connection {
    String host;
    int port;
}

public class Api {
    String baseUrl;
    String token;
}
```

Но в отличие от таблицы Excel, где каждая запись — это просто набор характеристик, объекты не ограничиваются перечнем свойств. ООП подразумевает, что объекты взаимодействуют друг с другом, а значит — обладают функциональностью, которую можно вызвать.

## Методы

Объекты умеют что-то делать:

- Человек может разговаривать, есть, спать
- Калькулятор — складывать, вычитать, умножать
- Соединение — открываться и закрываться
- API — отправлять HTTP-запросы

Перечень можно продолжать бесконечно долго. Можно, но не нужно. Как и со свойствами, перечень поведения определяется требованиями задачи.

В Java функциональность объектов описывается внутри классов в виде **методов**:

```java
public class Person {
    String name;
    int age;

    String getInfo() {
        return name + ", " + age;
    }
}

public class Calculator {
    double result;

    void add(double value) {
        result += value;
    }

    void subtract(double value) {
        result -= value;
    }
}

public class Connection {
    String host;
    int port;

    void open() {
        System.out.println("Opening connection to " + host + ":" + port);
    }

    void close() {
        System.out.println("Closing connection");
    }
}
```

## Создание объекта

Но как с этим всем работать?

Наверняка ты уже сталкивался с конструкциями вроде:

```java
String s = new String("Hello");
Object object = new Object();
```

Именно так из классов создаются объекты. Именно поэтому объекты называют **экземплярами классов**.

Здесь важны две вещи.

Первое — ключевое слово `new`. Именно оно инициирует процесс создания объекта.

Второе — то, что стоит после `new`, выглядит как вызов метода. Так оно и есть. Это специальный метод — **конструктор**. Конструкторы вызываются только в связке с `new` и отвечают за создание объекта.

## Конструктор

Конструктор нужен не только для того, чтобы создать объект. При создании объекта можно сразу задать его полям нужные значения:

```java
public class Person {
    String name;
    int age;

    Person(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

```java
Person person = new Person("Alex", 25);
```

Конструктор объявляется как метод, но без возвращаемого типа, и его имя совпадает с именем класса.

## this

В конструкторе выше параметр и поле называются одинаково — `name`. `this` — это ссылка на текущий объект. С её помощью явно указываем: слева — поле объекта, справа — параметр.

```java
Person(String name, int age) {
    this.name = name; // this.name — поле, name — параметр
    this.age = age;
}
```

Если имена параметров и полей не совпадают — `this` можно не писать. Но когда совпадают — без `this` не обойтись.

## Несколько конструкторов

У класса может быть несколько конструкторов с разными наборами параметров — это нормально. Это бывает удобно, когда объекты создаются в разных ситуациях с разным набором известных данных.

Например, у человека есть имя, возраст и номер телефона. Удобно завести конструктор со всеми параметрами. Но могут быть люди без номера телефона — для них удобнее отдельный конструктор, который номер телефона не принимает:

```java
public class Person {
    String name;
    int age;
    String phone;

    Person(String name, int age, String phone) {
        this.name = name;
        this.age = age;
        this.phone = phone;
    }

    Person(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

```java
Person withPhone = new Person("Alex", 25, "+79001234567");
Person withoutPhone = new Person("Maria", 30);
```

Это называется **перегрузкой** — одно имя, разные параметры. Мы разберём это подробнее в отдельном разделе.

## Конструктор по умолчанию

Если конструктор не объявлен явно — Java создаёт конструктор по умолчанию без параметров. Это значит, что объект можно создать вот так:

```java
public class Person {
    String name;
    int age;
}
```

```java
Person person = new Person(); // работает — конструктор по умолчанию создан Java автоматически
```

Как только объявляешь хотя бы один конструктор — конструктор по умолчанию исчезает. Если попробовать создать объект без параметров — будет ошибка компиляции:

```java
public class Person {
    String name;
    int age;

    Person(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

```java
Person person = new Person(); // ошибка: no suitable constructor found
```

Если нужны и конструктор с параметрами, и конструктор без параметров — нужно объявить оба явно:

```java
public class Person {
    String name;
    int age;

    Person() {
    }

    Person(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

Конструктор по умолчанию не обязан быть пустым. Если нужно задать полям особые начальные значения — это можно сделать явно:

```java
public class Connection {
    String host;
    int port;

    Connection() {
        this.host = "localhost";
        this.port = 5432;
    }
}
```

```java
Connection conn = new Connection();
System.out.println(conn.host); // localhost
System.out.println(conn.port); // 5432
```

## Вызов методов

Выше мы говорили что объекты обладают функциональностью. Объект создан — теперь можно вызвать его методы. Обращение к методам и полям — через точку:

```java
public class Person {
    String name;
    int age;

    Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    String getInfo() {
        return name + ", " + age;
    }
}
```

```java
Person person = new Person("Alex", 25);
System.out.println(person.getInfo()); // Alex, 25
System.out.println(person.name);      // Alex
```

Метод имеет доступ ко всем полям объекта, на котором вызван. Каждый объект хранит свои собственные значения:

```java
Person first = new Person("Alex", 25);
Person second = new Person("Maria", 30);

System.out.println(first.getInfo());  // Alex, 25
System.out.println(second.getInfo()); // Maria, 30
```

Это базовая информация о классах и объектах, которая тебе понадобится на каждом шагу. Несмотря на то что теория простая, её обязательно стоит закрепить на практике.
