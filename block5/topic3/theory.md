## Модификаторы доступа, геттеры, сеттеры

В данном материале мы познакомимся с модификаторами доступа.
В Java их 4: `public`, `private`, `protected` и package private — когда модификатор не указан вовсе.
Ниже разберёмся с каждым из них на примере реальных задач.

## Какую проблему решают модификаторы доступа?

Вспомним класс `BankAccount`:

```java
public class BankAccount {
    int balance;

    public BankAccount(int balance) {
        this.balance = balance;
    }

    public void deposit(int amount) {
        balance += amount;
    }
}
```

Несмотря на то что код рабочий, он обладает одним серьёзным недостатком. Ничто не мешает модифицировать баланс напрямую:

```java
BankAccount account = new BankAccount(1000);
account.balance = -99999;
```

Именно эту проблему решают модификаторы доступа. Они позволяют на уровне компиляции ограничить доступ к полям или методам объекта — или наоборот, расширить его.

## private

Для решения проблемы из примера выше мы можем закрыть доступ к переменной `balance` извне, дописав перед ней модификатор `private`:

```java
public class BankAccount {
    private int balance;

    public BankAccount(int balance) {
        this.balance = balance;
    }

    public void deposit(int amount) {
        balance += amount;
    }
}
```

Это самый строгий модификатор доступа. Он запрещает обращение к полю или методу извне. Но внутри самого класса доступ к приватным полям и методам остаётся.

Теперь `balance` защищён от изменений извне. Но мы не просто не можем его изменить — мы не можем к нему обратиться даже для того, чтобы просто узнать значение баланса.

То есть мы скрыли реализацию, но не предоставили механизма для взаимодействия с объектом.

К таким механизмам относятся специальные методы — **геттеры и сеттеры** (getter, setter).

Геттеры предназначены для получения значения (get — получать). Они ничего не принимают. Имя таких методов складывается из приставки `get` + имя поля, значение которого геттер вернёт.

Для `balance` из примера выше геттер выглядит так:

```java
public int getBalance() {
    return balance;
}
```

Теперь прочитать баланс можно, а напрямую изменить — нет:

```java
BankAccount account = new BankAccount(1000);
System.out.println(account.getBalance()); // 1000
account.balance = -99999;                 // ошибка компиляции
```

Сеттеры, в отличие от геттеров, задают значения (set — задать). Эти методы принимают в параметрах значение, которое необходимо присвоить защищённому полю. Имя таких методов складывается из приставки `set` + имя поля.

Мы могли бы добавить сеттер в `BankAccount`, но тогда потерялся бы смысл. Любой снова сможет поставить любое значение — только теперь через метод:

```java
account.setBalance(-99999); // ничем не лучше прямого обращения
```

Сеттер полезен тогда, когда внутри есть проверка. Возьмём класс `Person` с полем `age`. Возраст не может быть отрицательным — и именно сеттер позволяет это контролировать:

```java
public class Person {
    private String name;
    private int age;

    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public int getAge() {
        return age;
    }

    public void setAge(int age) {
        if (age < 0) return;
        this.age = age;
    }
}
```

```java
Person person = new Person("Alex", 25);
person.setAge(-5);
System.out.println(person.getAge()); // 25 — некорректное значение не прошло
```

Объект защитил себя. Это и есть **инкапсуляция** — не геттер и сеттер на каждое поле ради формальности, а осознанный контроль над состоянием объекта.

## public

`public` — противоположность `private`. Поле или метод с этим модификатором доступны отовсюду. Именно поэтому все методы, которые мы писали раньше, объявлялись как `public` — это явное решение открыть часть объекта внешнему миру.

Типичная практика: поля — `private`, методы — `public`. Данные скрыты, поведение доступно.

## package private

Если не указать ни один модификатор — это не значит "открыто всем". Это отдельный уровень доступа: **package private**. Такое поле или метод доступны только внутри того же пакета.

```java
class Helper {
    void doWork() { // package private — видно только внутри пакета
    }
}
```

Именно так мы объявляли поля в предыдущих задачах — намеренно, чтобы тесты из того же пакета могли к ним обращаться напрямую.

Package private удобен для вспомогательных классов и методов, которые нужны нескольким классам внутри одного пакета, но не должны быть видны снаружи.

## protected

Есть ещё один модификатор — `protected`. Он открывает доступ не только внутри пакета, но и для классов-наследников в других пакетах. Наследование — большая тема, к которой мы вернёмся позже. Тогда же `protected` встанет на своё место и станет понятен в контексте.

Пока достаточно знать что он существует и что по уровню открытости он находится между `private` и `public`.

Несмотря на то что теория простая, её обязательно стоит закрепить на практике.

## Резюме

### Модификаторы доступа

| Модификатор | Свой класс | Пакет | Наследник | Все | Пример |
|-------------|-----------|-------|-----------|-----|--------|
| `private` | ✅ | ❌ | ❌ | ❌ | `private int balance;` |
| package private | ✅ | ✅ | ❌ | ❌ | `int balance;` |
| `protected` | ✅ | ✅ | ✅ | ❌ | `protected int balance;` |
| `public` | ✅ | ✅ | ✅ | ✅ | `public int balance;` |

### Геттеры и сеттеры

**Геттер** — метод для чтения приватного поля.
- Не принимает параметров
- Возвращает значение поля
- Имя: `get` + имя поля с большой буквы

```java
public int getBalance() {
    return balance;
}
```

**Сеттер** — метод для изменения приватного поля.
- Принимает новое значение параметром
- Ничего не возвращает (`void`)
- Имя: `set` + имя поля с большой буквы
- Может содержать валидацию

```java
public void setAge(int age) {
    if (age < 0) return;
    this.age = age;
}
```
