# Особенности класса String

## Строки в памяти

В Java любой объект живёт в памяти. Переменная сама по себе не хранит строку — она хранит адрес, по которому строка лежит. Что-то вроде ярлыка, который указывает на нужное место.

```java
String a = "hello"; // a хранит адрес объекта "hello" в памяти
```

Для оптимизации Java не создаёт одинаковые строки дважды. Если написать:

```java
String a = "hello";
String b = "hello";
```

В памяти будет один объект `"hello"`, а обе переменные указывают на него. Убедиться можно так — `System.identityHashCode` это не настоящий адрес в памяти, но для демонстрации можно считать его таковым:

```java
String a = "hello";
String b = "hello";
System.out.println(System.identityHashCode(a)); // 123456
System.out.println(System.identityHashCode(b)); // 123456 — тот же объект
```

Всё дело в том, что все строковые литералы — то есть строки вида `"hello"`, написанные прямо в коде — при компиляции помещаются в единственном экземпляре в специальное хранилище, которое называется пулом строк. Переменные затем ссылаются именно на него. Благодаря этому одинаковые строки не дублируются в памяти. Сейчас это не главное — просто полезно понимать откуда берётся такое поведение.

## Иммутабельность

Когда строка создана и заняла место в памяти — её значение больше никогда не изменится. Можно создать новый объект, но изменить существующий — нельзя. Это свойство называется иммутабельностью.

На практике это выглядит вот как:

```java
String s = "hello";
System.out.println(System.identityHashCode(s)); // 123456

s = s.toUpperCase();
System.out.println(System.identityHashCode(s)); // 789012 — уже другой объект
```

`s` теперь указывает на совершенно другой объект в памяти. Старый `"hello"` никуда не делся, просто `s` больше на него не ссылается.

Если не сохранить результат — он просто потеряется:

```java
String s = "hello";
s.toUpperCase();        // создался новый объект, но никто на него не смотрит
System.out.println(s); // "hello" — s всё ещё указывает на старый объект
```

## Конкатенация и лишние объекты

Иммутабельность напрямую влияет на то, как работает склейка строк. Когда пишешь `+` — создаётся новый объект:

```java
String a = "hello";
String b = a + ", world"; // создаётся новый объект с результатом
```

В простых случаях это нормально. Проблема начинается в цикле:

```java
String result = "";
for (int i = 0; i < 1000; i++) {
    result = result + i; // каждую итерацию создаётся новый объект
}
```

Тысяча итераций — тысяча брошенных объектов в памяти. При большом количестве это ощутимо бьёт по производительности.

## StringBuilder

Именно для таких случаев придумали `StringBuilder`. Он работает как изменяемый буфер — позволяет добавлять, удалять и вставлять символы без создания новых объектов на каждый шаг.

```java
StringBuilder sb = new StringBuilder();
for (int i = 0; i < 1000; i++) {
    sb.append(i); // никаких лишних объектов
}
String result = sb.toString(); // получаем итоговую строку один раз
```

Основные методы:

```java
StringBuilder sb = new StringBuilder("Hello");
sb.append(", World"); // добавить в конец    → "Hello, World"
sb.insert(5, "!");    // вставить по индексу → "Hello!, World"
sb.delete(5, 6);      // удалить символы     → "Hello, World"
sb.toString();        // получить String
```

Простое правило: если склеиваешь строки в цикле — используй `StringBuilder`. В остальных случаях `+` достаточно.
